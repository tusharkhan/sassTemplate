How it works

One flag on the room

Captions are a room setting, not a separate service. Set the language when you create the room and every subscriber receives caption events on the session socket they are already connected to.

  • Partial hypotheses. Words appear as they are recognised and are corrected in place, so nothing waits for the end of a sentence.
  • Speaker labels. Diarisation runs alongside recognition, so each line carries the participant identity that produced it.
  • Translation on the same socket. Request additional target languages and they arrive as extra caption events, not a second connection.
  • Region-pinned inference. On Business plans the models run inside the region you selected, so audio never leaves it.

enable-captions.js

const room = await wave.rooms.create({
  name: 'all-hands-q3',
  ai: {
    captions: 'en',
    translateTo: ['de', 'ja', 'pt-BR'],
    vocabulary: projectVocabularyId
  }
});

// Subscribers receive one event per language.
session.on('caption', (line) => {
  if (line.lang !== viewerLocale) return;
  captionEl.textContent = line.text;
  captionEl.dataset.speaker = line.speaker;
});

Lines arrive as partial then final. Render partials for responsiveness and store finals for the transcript.

Accuracy

Where the errors actually come from

Generic models handle ordinary speech well and proper nouns badly. Custom vocabulary is the single biggest lever you have.

Measured word error rate by audio condition, with and without custom vocabulary
Condition Default With vocabulary
Studio microphone, one speaker 4.1% 3.6%
Laptop microphone, quiet room 6.8% 5.4%
Product names and rosters 18.2% 5.9%
Two speakers overlapping 11.4% 9.7%
Background music present 9.3% 8.8%

Figures are internal measurements on English audio. Treat model output as an aid, not an authoritative record — for accessibility or compliance transcripts, review them.
